 让研究助手可靠地将结果保存为文件

 背景

 运行 python -m harnesses research "深圳高三二模数学试卷难度分析报告" 后，LLM 的分析结果只输出到控制台，不会保存到文件。同时安全策略存在缺陷，导致 write 工具调用被错误拒绝。

 问题分析

 问题 1：安全策略顺序错误（核心）

 harnesses/base.py 的 read_only_path_policy() 返回的 policy 顺序：
 1. allow_read_only — 拒绝所有 mutate 工具（write, edit, etc.）
 2. allow_path_prefix(allowed) — 允许在 research 目录内的操作

 SecurityGate 执行第一个非 None 的 policy 就返回结果。allow_read_only 对 write 返回 DENY，所以 allow_path_prefix 永远不会被执行——即使写入路径在 research 目录内也被拒绝。

 问题 2：Pipeline 的 DENY 判断有 bug

 runtime/pipeline.py:121:
 if approval.decision.value == "DENY":
 Decision.DENY.value 是整数 2（来自 enum.auto()），而 "DENY" 是字符串。比较永远为 False，导致被拒绝的工具调用仍然执行——安全机制形同虚设。

 问题 3：CLI 不保存最终结果

 harnesses/cli.py:86-87: 只 click.echo(result.text)，不写入文件。

 问题 4：系统提示词不够明确

 提示词说 "Save important findings"，但没指定文件名约定、保存时机等。

 修改计划

 Step 1：修复 policy 顺序 — harnesses/base.py:42-51

 交换 read_only_path_policy() 中的 policy 顺序：
 1. allow_path_prefix(allowed) 先执行 — 对 research 目录内的 write 返回 ALLOW
 2. allow_read_only 后执行 — 兜底拒绝无路径参数的 mutate 工具（bash/exec）

 Step 2：修复 DENY 比较 — runtime/pipeline.py:121

 将 approval.decision.value == "DENY" 改为 approval.decision is Decision.DENY

 Step 3：CLI 保存最终结果 — harnesses/cli.py

 在 turn() 调用后保存 result.text 到 research_root/research-output-{YYYYMMDD-HHMMSS}.md。
 - 单次模式和 REPL 模式均生效
 - 不依赖安全策略，直接 Path.write_text()
 - REPL 模式下每次 turn 都保存

 Step 4：更新系统提示词 — harnesses/research.py

 - 明确文件名格式：{topic}-summary.md
 - 要求在分析最终完成后用 write 工具保存完整报告
 - 增加保存路径指示（research/ 目录）

 Step 5：更新测试 — tests/（如存在）

 - 修改 security test 断言：research 目录内的 write 应为 ALLOW
